## Separación realizada

- **frontend/** contiene src, public, index.html, Vite, configuración ESLint, package.json y tests de validadores.
- **backend/** conserva API, controladores, servicios, modelos SQL, rutas, middleware, configuración, scripts, esquema y tests; ahora tiene su propio package.json, ESLint y README.
- La raíz contiene solo la orquestación npm workspaces, un lockfile compartido, documentación y directorios generados/privados excluidos de Git.
- El entorno real se movió a backend/.env y la carga se resuelve desde el módulo, sin depender del directorio de la terminal.
- Vite lee únicamente frontend/.env; los secretos SQL, JWT, SMTP y OAuth no se comparten con el navegador.
- La salida pública ahora es frontend/dist. Express la sirve en producción sin exponer backend.
- Las rutas HTTP, políticas de contraseñas, sesiones, CSRF, roles, correo y decisiones OAuth permanecen funcionalmente iguales.
- La recarga de Express utiliza el modo watch nativo de Node.js 24, retirando nodemon y sus dependencias vulnerables. No se forzaron regresiones de paquetes.

npm workspaces puede compartir node_modules, pero cada paquete declara sus dependencias y responsabilidades. Instalar desde la raíz con npm ci y arrancar con npm run dev.

### Recorridos automatizados

Las suites existentes verifican registro y duplicados, privacidad de datos, permisos de usuario/admin, CSRF, CORS, contraseñas, revocación de sesiones, refresh concurrente, baja lógica, auditoría, permisos SQL, indisponibilidad de infraestructura y límites de intentos.

Se agregaron:

- Validadores del navegador y límites UTF-8 de contraseña.
- Contratos de separación de paquetes y ausencia de variables privadas en el ejemplo público.
- Verificación de correo obligatoria y código no reutilizable.

- Bloqueo tras tres contraseñas incorrectas y recuperación mediante código.

Las pruebas de integración usan PostgreSQL real en bases temporales de nombre generado y transporte de correo de prueba. No vacían ni alteran cuentas diarias, no envían mensajes reales y eliminan solo su propia base temporal al finalizar.

## Límites que no se ocultan

- No se completó un ingreso interactivo real con cada cuenta externa de Google/Facebook/GitHub/X. Se verificaron configuración, descubrimiento y contratos automatizados; el resultado final también depende de los permisos/cuentas del proveedor. Discord y Twitch no están configurados en esta copia.
- El modo producción exige TLS validado para PostgreSQL. El PostgreSQL portable local no tiene TLS: /api/health devuelve 503 en esa prueba de producción, como corresponde, y no se debilita la verificación para ocultarlo. Se comprobaron el HTML compilado, los recursos, rutas profundas, cabeceras y el 404 JSON de API. Para desplegar, configurar PostgreSQL con TLS y HTTPS.
- El análisis de la compilación comprobó que los valores privados configurados de SQL/JWT/SMTP/Auth0/admin no aparecen en los archivos públicos de texto.
- El ejercicio fue probado en navegador con tamaños móviles; no se usó un dispositivo físico.
- La base anterior se conservó, pero no se realizó recuperación forense ni migración de sus cuentas dañadas.
- Git advierte sobre conversión LF/CRLF según su configuración local; git diff --check no encontró errores de espacios. No se hicieron commits ni se modificó esa configuración.
